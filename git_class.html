Pré-requis

  • Git installé : git --version
  • Un compte GitHub
  • Terminal (macOS/Linux) ou PowerShell (Windows)

1) Initialiser un dépôt

Crée un dépôt Git dans un dossier existant :

Initialisation 
mkdir mon-projet
cd mon-projet
git init
git status

💡 git status te dit toujours “où tu en es”.

2) Cloner un dépôt

Récupérer un dépôt existant depuis GitHub :

Clone 
git clone https://github.com/USER/NOM_DU_REPO.git
cd NOM_DU_REPO
git status

3) Cycle classique : add → commit → push

Workflow minimal pour envoyer tes changements :

Add / Commit / Push 
git status
git add .
git commit -m "Message clair sur ce que j’ai changé"
git push

✅ Bonne pratique : commits petits et messages explicites.

4) Branches & merge

Créer une branche, bosser dessus, puis fusionner :

Branches 
git branch
git checkout -b feature/ma-fonctionnalite

# ... modifications ...

git add .
git commit -m "Ajoute la fonctionnalité X"
git checkout main
git merge feature/ma-fonctionnalite

5) Pull & conflits

Avant de pousser, pense à récupérer les changements distants :

Pull 
git pull
# si conflit : Git te le dit, tu ouvres les fichiers, tu résous, puis :
git add .
git commit -m "Résolution de conflit"
git push

🧯 Un conflit = Git ne sait pas choisir entre deux versions. Tu tranches.

6) GitHub Pages (mini check)

Pour un repo de site statique, assure-toi que index.html est à la racine (ou dans /docs si configuré ainsi).

Vérifier les fichiers 
ls
# tu dois voir index.html à la racine
# puis :
git add .
git commit -m "Update website"
git push
